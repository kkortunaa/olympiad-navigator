# Задания и варианты в ОлимпТреке

## Что реализовано

Учитель открывает **Варианты → Банк заданий** и создаёт задание: название, предмет,
тема, сложность, условие, необязательная иллюстрация, формат ответа, допустимые ответы,
правило сравнения, погрешность, разбор и авторство/источник. Поддерживаются PNG,
JPEG и WebP до 4 МБ. Условие отображается как текст с переносами строк и Unicode-
символами. HTML и программный код не исполняются. Внешние редакторы и архивы для
решения выданного варианта не нужны.

Вариант собирается из собственных заданий учителя. Можно менять порядок,
количество баллов и инструкцию. До 50 заданий, от 1 до 100 баллов за каждое.
Учитель выбирает класс, всех текущих участников или нескольких учеников, срок
по московскому времени и число попыток от 1 до 10. Присоединение нового ученика
не открывает ему ранее выданные работы автоматически: вариант нужно выдать ему
отдельно. Старые текстовые черновики из `classrooms.VariantDraft` доступны в новом
конструкторе с прежними названиями и инструкциями.

После выдачи в БД сохраняются **копии** условий, вариантов выбора, эталонов,
изображений, правил и баллов. Изменение банка/черновика не меняет уже выданную
работу. Архивирование задания скрывает его из обычного банка, сохраняя историю.
Старые изображения автоматически не удаляются, поскольку могут использоваться
в копиях ранее выданных заданий.

Ученик открывает **Задания** в шапке или вариант на странице класса/главной.
Попытку можно продолжить с другого устройства: ответы и прогресс хранятся в БД.
JavaScript сохраняет ответы через секунду после ввода. Есть отдельная кнопка
сохранения и обычная отправка формы без JavaScript. Конфликт версии возвращает
409 и не перезаписывает чужую вкладку. При ошибке сети поля остаются на экране,
появляется сообщение; уход с несохранёнными ответами вызывает предупреждение.

Завершение попытки проверяет весь вариант, включая пустые ответы. Завершённая
попытка неизменяема, повторная отправка не создаёт второе выполнение. В сводке
учитель видит лучший результат, при этом сохранены все попытки и ответы.
Одноклассники не видят чужие ответы, результаты и ошибки. Выход/исключение из
класса закрывают доступ через этот класс; история остаётся в БД. Уведомления о
выдаче и завершении используют существующую систему. Первое завершение варианта
добавляет одну запись в календарь активности, повторная попытка её не дублирует.

## Проверка и раскрытие ответов

Форматы:

| Формат | Правило |
| --- | --- |
| Короткий текст | Точное совпадение после удаления крайних пробелов либо без регистра и с объединением пробелов |
| Число | Точное рациональное сравнение или заданная учителем абсолютная погрешность. `1/2`, `0.5`, `0,5` равны |
| Один вариант | Номер выбранного ответа |
| Несколько вариантов | Полный набор номеров без учёта порядка, без частичного балла |

Каждая строка в поле правильных ответов — допустимая альтернатива. Для нескольких
вариантов одна строка может выглядеть как `1,3`. Числовые выражения не вычисляются:
`2+2` не превращается в `4`. Дроби, десятичные числа и ограниченная экспоненциальная
запись поддерживаются. Эссе, доказательства, фотографии ученического решения и
запуск программ автоматически не оцениваются. Для таких работ можно использовать
прежние текстовые задания и ручное обсуждение с преподавателем.

Три режима проверки:

1. После каждого ответа: ученик нажимает «Проверить ответ». Изменение ответа снова
   скрывает его прежнюю оценку до очередной проверки.
2. После завершения: оценки и разборы открываются после отправки всей попытки.
3. После срока: даже завершивший раньше ученик не видит оценки/статистику этой работы
   до дедлайна. Нужна дата и время окончания.

Отдельное разрешение учителя управляет показом эталонов и разборов. Если оно
выключено, ученик видит оценку в разрешённый момент, но не правильный ответ,
объяснение учителя и ИИ. Эталоны и разборы отсутствуют в HTML, полях формы и JSON
ответах до открытия. Отправка прямого запроса к ИИ не обходит эти правила.

После дедлайна новые ответы не принимаются. При открытии списка/работы/ведомости
сохранённые ответы начатых попыток автоматически оцениваются. Планировщик и
постоянный процесс для этого не нужны. Время завершения фиксируется при такой
проверке. Ученик, который вообще не начинал работу, остаётся с отметкой
«Не приступил», без выдуманной нулевой попытки.

Статистика считает ответы из завершённых и уже открытых ученику попыток.
Повторные попытки учитываются отдельно. Учитель видит ошибки по заданиям,
количество ошибившихся учеников и темы для повторения. Ученик видит собственные
темы и ссылки к заданиям, где ошибался. Это показатели ответов, а не измерение
общего уровня знаний.

## Необязательный ИИ-помощник

Провайдер: **Groq**, модель по умолчанию `openai/gpt-oss-20b`. API используется
через стандартную библиотеку Python, дополнительные пакеты не нужны. На момент
проверки 22.10.2026 модель присутствует в таблице бесплатного тарифа Groq.
Лимиты и доступность зависят от аккаунта и могут меняться. Сайт не включает
платный тариф и не переключается автоматически на платного провайдера.

Официальные источники:

- [Бесплатные лимиты Groq](https://console.groq.com/docs/rate-limits)
- [API Groq](https://console.groq.com/docs/openai)
- [Модель GPT OSS 20B на Groq](https://console.groq.com/docs/model/openai/gpt-oss-20b)
- [Разрешённые адреса бесплатного PythonAnywhere](https://www.pythonanywhere.com/whitelist/)

Кнопка «Объяснить решение» доступна только после разрешённого открытия разбора.
В Groq передаются условие, предмет, тема, варианты выбора, эталон и объяснение
учителя. Имена, логины, email, ученические ответы, чат, класс и история не
передаются. Ученик видит сообщение об этой передаче рядом с кнопкой.

Модель получает инструкцию объяснить способ по шагам, проверить вычисления и
сверить итог с эталоном. Сервер дополнительно проверяет последнюю строку
«Ответ: …» тем же алгоритмом, что ученические ответы. Несовпадение, оборванный
ответ или ошибка API заменяются объяснением учителя. Это **не доказательство
правильности всех шагов ИИ**: он может подогнать итог или ошибиться в объяснении.
Рядом с разбором всегда есть соответствующая пометка.

В этой версии ИИ работает с текстом. Для заданий с изображением используется
разбор учителя, чтобы текстовая модель не придумывала содержимое иллюстрации.
Если ключа нет, квота исчерпана, API недоступен, ответ неверен или слишком длинный,
сайт продолжает работать. Если разбор учителя не добавлен, показывается понятное
сообщение о недоступности вместо выдуманного решения.

Лимиты сохраняются в БД и общие для процессов сервера. По умолчанию 10 новых
запросов на ученика в сутки, 50 на сайт, пауза 15 секунд, таймаут 20 секунд,
до 1800 выходных токенов. Ошибочный вызов тоже расходует локальный лимит.
Повторный разбор того же задания с теми же параметрами берётся из кеша и квоту
провайдера не расходует. Условие вместе с контекстом ограничено 12000 символами,
ответ провайдера — 8000 символами. HTML в разборе не исполняется.

Переменные окружения:

```text
GROQ_API_KEY=ключ_только_на_сервере
PRACTICE_AI_MODEL=openai/gpt-oss-20b
PRACTICE_AI_USER_DAILY_LIMIT=10
PRACTICE_AI_GLOBAL_DAILY_LIMIT=50
PRACTICE_AI_COOLDOWN=15
PRACTICE_AI_TIMEOUT=20
PRACTICE_AI_MAX_TOKENS=1800
```

Для отключения ИИ достаточно убрать `GROQ_API_KEY`. Нулевой дневной лимит также
запрещает новые запросы. Не кладите ключ в HTML, JavaScript, Git или скриншоты.
Локальный файл `.env.practice` исключён из Git, но автоматически не читается:
переменные задаются процессу Django/WSGI.

## Обновление PythonAnywhere

Сначала отправьте эти изменения в репозиторий из локального checkout. Затем в
Bash-консоли PythonAnywhere (для существующей установки):

```bash
cd /home/kkortunaa/olympiad-navigator
git pull
source .venv-app/bin/activate
cd scuns
python -c "import sqlite3; from pathlib import Path; from datetime import datetime; Path('.backups').mkdir(exist_ok=True); s=sqlite3.connect('db.sqlite3'); d=sqlite3.connect('.backups/before-practice-'+datetime.now().strftime('%Y%m%d-%H%M%S')+'.sqlite3'); s.backup(d); d.close(); s.close()"
python manage.py migrate
python manage.py collectstatic --noinput
mkdir -p media
python manage.py check
```

Если база задана через `DJANGO_DB_PATH`, делайте копию именно этого файла.
Перед командами задайте тот же `DJANGO_SETTINGS_MODULE`/производственные переменные,
которые использует ваш WSGI. Миграция `practice.0001_initial` добавляет таблицы,
существующие аккаунты, каталоги, чаты и черновики не удаляет. Демо-задания в рабочую
базу автоматически не добавляются.

На вкладке **Web → Static files**:

| URL | Directory |
| --- | --- |
| `/static/` | `/home/kkortunaa/olympiad-navigator/scuns/staticfiles` |
| `/media/` | `/home/kkortunaa/olympiad-navigator/scuns/media` |

`/media/` содержит только пользовательские иллюстрации и ранее существовавшие
аватары. Имена файлов иллюстраций случайные; ответы/разборы не сохраняются в эту
папку. После изменения сопоставлений нажмите **Web → Reload**.

Для ИИ создайте ключ в [консоли Groq](https://console.groq.com/keys), используя
бесплатный тариф. Сохраните его текстом в приватном файле
`/home/kkortunaa/.groq-api-key` через файловый редактор PythonAnywhere и ограничьте
права:

```bash
chmod 600 /home/kkortunaa/.groq-api-key
```

В **существующем** WSGI-файле PythonAnywhere до импорта/создания приложения Django
добавьте чтение файла в окружение, сохранив остальную конфигурацию:

```python
import os
from pathlib import Path

key_path = Path('/home/kkortunaa/.groq-api-key')
if key_path.exists():
    os.environ['GROQ_API_KEY'] = key_path.read_text().strip()
os.environ.setdefault('PRACTICE_AI_MODEL', 'openai/gpt-oss-20b')
```

Снова **Reload**. Один `export` в отдельной Bash-консоли не передаёт ключ уже
запущенному WSGI. На бесплатном PythonAnywhere `api.groq.com` находится в списке
разрешённых адресов; стандартный urllib использует настроенный сервером HTTPS-
прокси. При сетевой ошибке остаётся разбор преподавателя.

## Файлы и проверка

- `practice/models.py`: банк, состав варианта, копии выданных заданий, получатели,
  попытки, ответы, квоты и кеш ИИ.
- `practice/grading.py`, `services.py`: сравнение, выдача, сохранение версий,
  завершение, дедлайны и статистика.
- `practice/ai.py`: серверный вызов Groq, ограничения, проверка итогового ответа.
- `practice/forms.py`, `views.py`, `urls.py`, `templates/practice/`: сценарии и доступ.
- `static/navigator/practice.css` и `practice.js`: обе темы, телефон, автосохранение.

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test
```

Тесты работают с отдельной БД. Вызовы Groq в автоматических тестах подменяются:
проверяются правильный результат, несовпадающий итог, обрыв, отсутствие ключа,
ошибка авторизации/квоты, таймаут, кеш, ограничения и отсутствие персональных
данных в запросе. Настоящий вызов требует вашего серверного API-ключа.
