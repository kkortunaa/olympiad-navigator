# Как работает «Олимпиадный навигатор»

Состояние проекта проверено 13 октября 2026 года. Это работающий локальный Django-сервис. Публичное размещение сайта пока не настроено.

## 1. Что где находится

| Раздел | Для чего нужен |
| --- | --- |
| Главная | Задачи подготовки на выбранный день или за все даты; календарь выполненных задач за год |
| Олимпиады → Каталог | Поиск, предмет, уточнение профиля, сроки регистрации, сортировка, избранное |
| Олимпиады → Мои олимпиады | Избранные олимпиады и олимпиады из задач; предупреждения о пересечении дат туров |
| Подготовка | Ссылки на архивы заданий; добавление задачи разбора на сегодня |
| Уведомления | Приближающиеся сроки и просроченные задачи; настройки напоминаний |
| Кабинет | Имя, смена пароля, перенос гостевых данных, скачивание и восстановление копии, выход |

Отдельная вкладка «Мой план» удалена. Старые адреса `/plan/`, `/list/`, `/sunc/` перенаправляют на главную. Каталог олимпиад с главной убран.

## 2. Предмет и профиль простыми словами

**Предмет** — общая школьная область: математика, информатика, история, русский язык и т. д.

**Профиль** — конкретное направление олимпиады. Например, профиль «Компьютерная безопасность» связан с предметом «Информатика». Один профиль может относиться к нескольким предметам. У разных профилей одной олимпиады могут отличаться уровень, сроки и регистрация.

Иногда предмет и профиль одинаково называются: «История» или «Математика». Это объясняет кажущееся повторение. Поэтому в интерфейсе предмет оставлен основным фильтром, профиль спрятан в необязательное уточнение. При смене предмета уточнение профиля сбрасывается, чтобы прежнее скрытое условие не мешало поиску.

Поиск предметов и профилей работает по вводу текста. Статус регистрации выбирается кнопками. Сброс возвращает и фильтры, и исходную сортировку по ближайшему окончанию регистрации. Есть отдельная кнопка «Избранное».

## 3. Как считается активность

Годовой календарь похож на календарь вкладов GitHub. Клетка означает день; цвет показывает число выполненных задач: 0, 1, 2–3, 4–6, 7 и больше. Есть сумма за год, число активных дней и лучшая непрерывная серия **в пределах выбранного года**.

У задачи теперь две разные даты:

- запланированная дата — когда ты собирался её делать;
- `completed_on` — когда поставил отметку «выполнено», по московскому времени.

В календарь попадает вторая дата. Изменение запланированного дня не переносит выполненную работу в истории. Повторные перезагрузки и клики не создают дополнительные выполнения одной задачи.

История хранится отдельно, в `activity`: ID задачи → дата выполнения. Удаление завершённой задачи сохраняет её вклад. Снятие отметки отменяет выполнение. Повторная отметка учитывает задачу один раз на новую дату. Это личный учёт, без проверки того, действительно ли решено задание.

Для старых завершённых задач дата выполнения неизвестна. Они остаются выполненными, но не включаются в календарь; интерфейс объясняет это. Выдуманных прошлых дат и демонстрационной активности нет.

На телефоне календарь прокручивается внутри виджета, открывая текущий месяц. Страница целиком по горизонтали не прокручивается. Дни можно выбирать мышью или стрелками клавиатуры.

## 4. Что происходит при открытии сайта

1. Браузер запрашивает страницу у Django, например `/olympiads/`.
2. Django находит нужный обработчик по адресу и читает данные через ORM — слой Python, который выполняет SQL-запросы.
3. Каталог, профили и события берутся из SQLite. Если пользователь вошёл, Django также получает его личные данные и проверяет сессию.
4. Django собирает HTML из шаблонов. Браузер загружает CSS для оформления и обычный JavaScript для кнопок, фильтров, задач и календаря.
5. Фильтрация каталога и подсчёт активности происходят в браузере. При отметке задачи вошедший пользователь отправляет JSON на `/api/workspace/`.
6. Сервер проверяет сессию, CSRF, формат, лимиты и номер версии. Затем сохраняет новое состояние в базе.

Selenium при каждом открытии страницы **не запускается**. Пользователь читает уже собранные данные, поэтому скорость сайта не зависит от загрузки страниц организаторов.

## 5. Что хранится в базе

Одна SQLite-база `scuns/db.sqlite3` содержит разные таблицы:

| Модель/таблица | Данные |
| --- | --- |
| `Olympiad` | Сезон, номер в перечне, название, сайт и регистрация, состояние обновления |
| `OlympiadProfile` | Профиль, предметы, уровень, регистрация и ссылка на архив заданий |
| `OlympiadEvent` | Регистрация или тур, даты, профиль, место/формат, исходный текст и источники |
| `ScrapeRun` | Журнал запусков парсера: результат, время, количества, ошибки |
| `users.MyUser` | Логин, хеш пароля, имя и стандартные поля пользователя Django |
| `planner.Workspace` | Личные задачи, история активности, избранное и настройки в JSON; номер версии |
| `django_session` | Сессии входа |

Проверено наличие таблиц аккаунтов, личных данных и сессий. После дополнительной сверки регистрации в активном каталоге 60 олимпиад, 272 профиля и 397 событий. Это сохранённое состояние, а не гарантия полноты опубликованных дат. Ссылки на архивы есть у 268 профилей; сами PDF и решения на сайт не копируются.

## 6. Как парсер обновляет каталог

Парсер — отдельная команда Django:

```bash
python manage.py sync_olympiads --season 2026/2027
```

Её запускают из папки с `manage.py` после активации окружения.

1. Selenium управляет отдельным Chrome через ChromeDriver и открывает публичные страницы источников.
2. Официальный перечень РСОШ определяет состав олимпиад, профили, предметы и уровни. Страницы Олимпиада.ру используются для сопоставления и расписаний.
3. BeautifulSoup разбирает полученный HTML. Парсер проверяет сезон, соответствие профиля, даты и ссылки.
4. Начало регистрации и её окончание записываются в разные поля. Если дата не опубликована, она остаётся неизвестной.
5. Записи обновляются по устойчивым ключам: сезон и номер олимпиады; для события — олимпиада, профиль и ссылка. Повторный запуск не должен создавать дубли.
6. Ошибки сохраняются в журнал. При недоступном источнике прежние проверенные данные сохраняются. Устаревшие события отключаются при успешном полном чтении соответствующего расписания.
7. Ссылки регистрации и архивов обновляются отдельно от личных задач пользователей.

Пример: для информатики Всесибирской олимпиады открытие регистрации — 19.10.2026, окончание — 06.11.2026, тур — 08.11.2026.

Для повторения каждые шесть часов есть:

```bash
python manage.py sync_olympiads --watch --interval 21600
```

Обновления идут, **пока этот процесс запущен** и есть сеть. Сам запуск веб-сервера не запускает парсер. Постоянная служба обновления на хостинге пока не настроена. Для архивов есть отдельная команда `python manage.py sync_task_links`.

## 7. Работают ли аккаунты и смена пароля

Базовые сценарии работают и проверены автоматическими тестами:

- регистрация создаёт пользователя и его личное пространство;
- пароль сохраняется как хеш, а не открытый текст;
- вход проверяет пароль; выход выполняется POST-запросом;
- один пользователь не читает и не изменяет личное пространство другого через API;
- сохранение требует CSRF-токен;
- смена пароля требует старый пароль и два совпадающих новых;
- неправильный старый пароль отклоняется;
- после смены старый пароль перестаёт подходить, новый подходит;
- текущая сессия сохраняется, прежние сессии требуют нового входа.

**«Забыл пароль» по email, подтверждение email и двухфакторный вход пока отсутствуют.** Смена известного пароля и восстановление забытого — разные функции.

При сохранении есть задержка 350 мс, чтобы не отправлять запрос на каждый символ. Другие вкладки проверяют изменения раз в 45 секунд. Если два устройства редактировали старую версию, сервер отвечает конфликтом версии и предлагает скачать свою копию и загрузить свежие данные. Автоматического объединения одновременно отредактированных полей нет.

При проблеме соединения показывается ошибка, а несохранённый черновик остаётся в `sessionStorage` вкладки, если браузер позволяет. Это не замена серверной резервной копии. В кабинете есть экспорт и восстановление JSON.

Гостевой режим использует `localStorage` данного браузера. Он не синхронизируется между компьютерами. Перенос гостевых данных в аккаунт выполняется отдельной кнопкой кабинета.

## 8. Ограничения

| Что | Текущий предел |
| --- | --- |
| Хранящиеся задачи | 1000 на аккаунт, включая завершённые |
| Название задачи | 180 символов |
| История выполнения | 5000 задач, включая удалённые завершённые |
| Избранное | До 1000 записей; фактически каталог меньше |
| Прочитанные уведомления | До 2000 идентификаторов |
| Запрос сохранения / импортируемая копия | 2 000 000 байт |
| Неудачные входы | 10 для пары IP/логин, затем блокировка до истечения 5 минут от последней неудачной попытки |
| Пароль | От 8 символов; стандартная проверка Django против распространённых, полностью числовых и слишком похожих на логин паролей |
| Сессия | 14 дней по текущей настройке; может завершиться раньше после выхода или смены пароля |

Платных тарифов, суточной квоты на задачи, заданного максимального числа аккаунтов и ограничения на число одновременных устройств в коде нет. Максимальное число одновременно работающих пользователей нагрузочным тестом не определялось. SQLite и JSON-сохранение целого личного пространства имеют практические ограничения по параллельным изменениям.

Ограничение входов сейчас использует локальный кеш процесса. Для нескольких процессов нужен общий кеш или ограничение на сервере перед Django.

## 9. Можно ли войти с другого ПК

**Да, если оба компьютера открывают один и тот же сервер сайта.** Тест с двумя независимыми клиентами подтвердил, что второй вход получает сохранённые задачи и историю первого.

Сейчас адрес `http://127.0.0.1:8000/` работает на компьютере, где запущен Django. На другом компьютере `127.0.0.1` означает уже тот другой компьютер. Для обычного доступа нужен размещённый сервер с доменом и HTTPS либо отдельно настроенный доступ внутри локальной сети. Копирование проекта с отдельным файлом базы на другой ПК создаёт отдельную копию данных, а не синхронизацию.

Локальный запуск с `DEBUG=True` не является завершённой подготовкой публичного сервера. Для размещения ещё нужны конфигурация рабочего веб-сервера, постоянное выполнение парсера, резервные копии, работа со статикой и проверка зависимостей. Настройки `DJANGO_DEBUG`, `DJANGO_SECRET_KEY` и `DJANGO_ALLOWED_HOSTS` уже предусмотрены.

## 10. Мои олимпиады, совпадения и уведомления

Выбор статуса участия удалён из всех страниц. Раздел «Мои олимпиады» собирает избранное и олимпиады, для которых есть задачи подготовки. Кнопка «Зарегистрироваться» ведёт на внешний сайт; наш сервис не отправляет заявку организатору и не получает результат олимпиады.

Предупреждения и напоминания относятся к этому списку олимпиад. Для многопрофильной олимпиады учитываются все профили. Совпадения сравнивают разные олимпиады по полностью известным будущим периодам туров. Общий тур с одним идентификатором источника не дублируется для каждого профиля. Это возможные пересечения, а не подтверждение, что пользователь участвует во всех перечисленных профилях. Часы модель пока не хранит.

Напоминания включают опубликованные сроки регистрации, начало туров, задачи на сегодня и просроченные задачи. Есть настройка за 1/3/7/14 дней и отметка прочтения. Системные уведомления браузера включаются пользователем на конкретном устройстве и доставляются, пока сайт открыт. Фонового Web Push, email и Telegram нет.

Если источник сообщает только «До 1 декабря», дата окончания показывается независимо от неизвестной даты открытия. Для СПбГУ подтверждённое окончание регистрации — 01.12.2026, отборочный этап — 20.10–01.12.2026. Регистрация отображается первой в таблице, большой блок выбора статуса перед расписанием удалён. Архивы заданий доступны в нижней таблице профилей.

Если подтверждённого дедлайна в сохранённых данных нет, но известна дата начала отборочного тура, показывается **«Предположительно до …»**. Такой ориентир не записывается в `OlympiadEvent` как опубликованная регистрация и не вызывает уведомления о подтверждённом дедлайне. Он доступен в карточке, на странице олимпиады и отдельно в API как `registration_estimates`. Подтверждённый срок всегда имеет приоритет. Если неизвестны и дата регистрации, и начало отбора, дата не придумывается.

Дополнительная сверка пропусков через Selenium:

```bash
python manage.py refresh_registration_dates --driver-path /path/to/chromedriver
```

Она обновляет только события регистрации, не удаляет расписания туров и сохраняет отчёт `registration-refresh-report.json`. Последняя сверка 13.10.2026 обновила 11 событий, из них 2 добавлены впервые, без ошибок чтения.

## 11. Что улучшить следующим

1. **Размещение и надёжность:** один сервер для всех устройств, HTTPS, резервные копии, постоянное обновление каталога. При росте нагрузки — PostgreSQL и общий кеш.
2. **Восстановление доступа:** email, подтверждение адреса, ссылка «Забыл пароль»; затем при необходимости двухфакторный вход.
3. **Напоминания при закрытом сайте:** фоновая очередь и email, Telegram либо Web Push с выбором канала и времени.
4. **Личный календарь:** экспорт выбранных туров в ICS для Google/Apple/Outlook; хранение точного времени и часового пояса, когда они опубликованы.
5. **Подготовка по темам:** предмет и тема задачи, ссылка на условие, заметки об ошибках, повторение трудных задач, недельная цель. Это даст календарю активности содержательную статистику.
6. **Персональный подбор:** класс, предметы, доступные уровни, формат и место проведения; сохранённые наборы фильтров и ссылки на результаты поиска.
7. **Защита от случайных действий:** отмена удаления задачи и архив завершённых, журнал изменений дедлайнов и уведомление об изменившейся дате.

## 12. Что проверено

До последнего изменения оформления и удаления выбора статуса 13.10.2026 прошли **82 Django-теста**, включая прежние проверки парсера и новые проверки аккаунтов, смены пароля, CSRF, раздельности данных, двух сессий, конфликтов версий, истории активности, лимитов и структуры страниц. Дополнительно проверены синтаксис четырёх JS-файлов и шесть сценариев расчёта календаря: високосный/обычный год, сумма и серия, исключение будущего, градации цвета, выравнивание недели.

В браузере проверены добавление и выполнение временной задачи, сохранение счётчика после перезагрузки, отмена выполнения, «Все даты», переход из просроченного напоминания, поиск предмета/профиля, сортировка, сброс, избранное, раздел участия и меню на ширине 390 px. Тестовая задача удалена после отмены выполнения; вымышленной активности не оставлено. Ошибок JS в просмотренных сценариях не зафиксировано.

Прогоны выполнены в текущем окружении Python 3.9 / Django 4.2.30. В `requirements.txt` пока закреплён Django 3.2.16; чистая установка из него этими прогонами не проверялась. Перед размещением стоит согласовать зависимости и повторить проверки в окружении сервера.

Это проверка перечисленных сценариев, а не доказательство отсутствия всех ошибок или готовности к большой нагрузке. Полный сетевой сбор олимпиад в рамках изменения дизайна повторно не запускался.

## 13. Оформление и последняя проверка страниц

13.10.2026 добавлена чёрно-фиолетовая тема по предоставленному HTML-макету: графитовые поверхности, лавандовые кнопки, небольшие предметные значки, закладки избранного и единое оформление всех разделов. Значки декоративные, не официальные логотипы организаторов. Основные стили оформления находятся в `scuns/static/navigator/midnight.css`.

После изменения просмотрены главная, каталог, страница расписания СПбГУ, «Мои олимпиады», подготовка и вход; адаптивное оформление просмотрено на ширине 390 px. Выполнены проверка синтаксиса и Django system check. Автоматические тесты на этом этапе не добавлялись и не запускались. Предыдущий результат 82 тестов относится к состоянию до этих изменений. Старое поле `participation` в копиях данных сохранено для совместимости, но больше не используется интерфейсом и напоминаниями.

## 14. Место проведения тура

Рядом с датами появилась колонка «Место проведения». В базе у каждого тура отдельно
сохраняются формат, опубликованное описание места, ссылка на площадки (если найдена),
источник, подтверждающий текст, тип источника и время проверки. Эти же сведения доступны в API.

Парсер сначала разбирает страницу самого события, затем описание соответствующего
профиля. Описание отбора не переносится на финал и наоборот; общий адрес университета
и город в шапке сайта не считаются площадкой. Общая отметка «Очно-заочная» не
превращается автоматически в дистанционный отбор: в некоторых олимпиадах сам отбор очный.

Данные из описания профиля отмечены явно, а исходный текст можно раскрыть кнопкой
«Подробности». Для очного тура с неизвестной площадкой предлагается уточнить сведения
у организатора. Точный адрес не придумывается, если опубликован только город или формат.

Для отдельного обновления используется `python manage.py sync_venues`; обычный полный
парсер также обновляет эти поля. 13.10.2026 обработан 301 тур через Selenium без ошибок
чтения. После отдельной проверки неоднозначных привязок у 150 туров есть формат или
описание места, у 7 из них — описание площадки/города. 151 остаётся без подтверждения.

После изменения выполнены проверка конфигурации Django, проверка миграций, синтаксиса
Python и просмотр расписания в браузере. Новые автоматические тесты не запускались.

## Классы и роли (15.10.2026)

- `users.MyUser.role`: `student` (по умолчанию) / `teacher`, независим от `is_staff`.
- Приложение `classrooms`: `Classroom`, `Membership`, `Invitation`,
  `StudentRegistration`, `Assignment`, `AssignmentReceipt`, `ChatMessage`,
  `SchoolNotice`, `VariantDraft`. Миграции: `users.0002_myuser_role` и
  `classrooms.0001_initial`.
- `classrooms/views.py`: авторизация по роли и владельцу, POST для изменений,
  CSRF, страницы классов и ответы JSON для чатов/уведомлений.
- `classrooms/services.py`: счётчики активности и календарь из подтверждённых
  учеником отметок регистрации по профилям. Отметка не подтверждает запись у
  организатора или допуск к следующему этапу.
- `AssignmentReceipt` — отдельный источник выполнения заданий учителя.
  В `Workspace.state.activity` оно записывается как `school-assignment-ID`.
  Обновление увеличивает ревизию Workspace; устаревшие сохранения возвращают 409.
  При повторном сохранении ответа дата выполнения сохраняется. Отмена удаляет
  запись активности; суммарные счётчики используют объединение идентификаторов.
- `Membership.is_active=False` закрывает доступ к истории, не удаляя её.
  Регистрации и личный Workspace остаются собственностью ученика.
- В `personal-bootstrap.registered_profiles` — актуальные отметки ученика.
  Клиентский `registered` выводится из них, не является редактируемым статусом
  участия и не принимается как авторитетное поле JSON Workspace.
- `school.js`: календарь по клику/подсказкам, опрос чата 5 с, уведомлений 20 с,
  сохранение черновика сообщения в sessionStorage с ключом пользователя/класса.
- `theme.js`, `light.css`, `school.css`: переключатель темы, сохранённый выбор,
  адаптивные страницы классов. При светлой теме `midnight.css` отключается;
  общий `site.css` и стили классов остаются включены.
- «Варианты» — только сохраняемые планы. Источник заданий не подключён.
